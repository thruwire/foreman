# Foreman 0.5.0

This release adds LangChain Deep Agents Code (`dcode`) to Foreman core as both a
headless worker backend and an agent harness supervised through native hooks.

- Select `FOREMAN_WORKER_BACKEND=deepagents` to run coding and verification jobs
  through the separately installed CLI. Configure its executable, model, turn
  limit, and shell allow-list through Foreman's environment settings.
- Stream bounded output from both pipes, enforce worker deadlines, recognize
  native budget exhaustion, and stop descendant process groups, including the
  separate LangGraph server, during supervisory termination.
- Use `foreman hook --client deepagents` for seven native lifecycle events,
  including tool failures, completion checks, and session cleanup. Existing
  responsibilities, routing, evidence, and completion allowances apply.
- Run `foreman deepagents setup` to merge native Hooks v2 handlers atomically
  while preserving other settings. Repeating setup with the same executable
  does not duplicate handlers.
- Follow the [installation and setup guide](../../integrations/deepagents/README.md)
  for provider credentials, repository scope, custom paths, and troubleshooting.

Foreman keeps Python 3.11+ support and gains no LangChain SDK dependency. Install
`deepagents-code >= 0.1.83` separately with Python 3.12+. Native hooks and the
worker were tested with CLI 0.1.83 and SDK 0.7.23.

Live OpenAI runs on isolated copies of the sample calculator repository passed:
Foreman launched a coding worker and independent verifier, reached `FINISHED`,
and passed 36 tests; the separate autonomous native-hook run passed 34 tests and
all 26 hook invocations. The original sample repository remained unchanged.
See the [live test report](../../integrations/deepagents/live-test-results.md)
for scope and limitations.

The automated suite passes 430 Python tests. Native post-tool stop directives
provide model feedback; pre-tool denial and Stop handle their respective control
boundaries. The headless worker uses stop/retry steering. This integration does
not configure a sandbox, and its shell allow-list should match the project.

Since 0.4.4, the repository also documents OpenRouter setup through the TypeSafe
SDK and pins GitHub Actions to immutable commits for CI and publishing.
